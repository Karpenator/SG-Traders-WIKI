# Лояльность и репутация

[🇬🇧 English version](EN-Loyalty-And-Reputation)

**Что это:** прогрессия игрока у каждого торговца. От неё зависят доступные товары и скидка. Настраивается полями `LoyaltyThresholds`, `LoyaltyReputationThresholds`, `TurnoverReputationEnabled`, `TurnoverReputationInterval`, `TurnoverReputationGain` в файле торговца и `LoyaltyDiscountStep` в главном конфиге.

---

## Две отдельные величины

| Величина | Что это | Диапазон |
|---|---|---|
| **Оборот** | Сумма всех сделок игрока с этим торговцем: покупки, бартеры и продажи. Только растёт. | 0 … 2 000 000 000 |
| **Репутация** | Отдельная «шкала доверия». | 0.00 … 9.99 |

Обе считаются **отдельно для каждого торговца**: у Прапора может быть 4 уровень, у Миротворца — 1.

Оборот начисляется так:

* покупка → плюс фактическая уплаченная сумма (уже со скидкой);
* продажа → плюс полученная сумма;
* бартер → плюс сумма базовых цен отданных предметов.

Репутация растёт тремя способами: за шаги оборота (ниже), наградами заданий из `SG_Quest` и вручную через админ-панель.

---

## Как считается уровень лояльности

Уровней четыре. Первый — бесплатный, остальные три задаются порогами:

```json
"LoyaltyThresholds": [ 12000, 45000, 120000 ],
"LoyaltyReputationThresholds": [ 0.04, 0.09, 0.15 ]
```

Первое число — для уровня **II**, второе — для **III**, третье — для **IV**.

Алгоритм простой: уровень начинается с 1 и поднимается на единицу за каждый порог, который игрок **прошёл по обеим шкалам сразу**:

```
уровень = 1
для каждого порога i:
    если оборот < LoyaltyThresholds[i]        → порог не пройден
    если репутация < LoyaltyReputationThresholds[i] → порог не пройден
    иначе                                     → уровень +1
максимум — 4
```

Пример для Прапора (пороги 12 000 / 45 000 / 120 000 и репутация 0.04 / 0.09 / 0.15):

| Оборот | Репутация | Уровень | Почему |
|---|---|---|---|
| 20 000 | 0.02 | **I** | Оборот для II есть, репутации 0.04 не хватает |
| 20 000 | 0.05 | **II** | Первый порог пройден по обеим шкалам |
| 50 000 | 0.05 | **II** | Для III нужна репутация 0.09 |
| 50 000 | 0.10 | **III** | Два порога пройдены |
| 500 000 | 0.10 | **III** | Для IV нужна репутация 0.15 |
| 500 000 | 0.15 | **IV** | Все три порога пройдены |

### Если пороги репутации не заданы

`"LoyaltyReputationThresholds": []` — уровень зависит **только от оборота**. Так настроен Скупщик (`FENCE`).

Можно задать и частично: если в списке два числа, то для уровня IV репутация не требуется.

### ⚠️ Уровень не хранится — он вычисляется каждый раз

Это важно понимать перед правкой порогов:

* Игрок нигде не «записан» как игрок 3 уровня. Уровень пересчитывается из его оборота и репутации при каждом обращении.
* **Поменяли пороги — уровни всех игроков изменились сразу**, при следующем открытии доски.
* Уменьшили порог — все мгновенно выросли. Увеличили — половина сервера упала на уровень.

Если хотите «обнулить прогресс» — удаляйте файлы в `players\`, а не занижайте пороги.

## Скидка за лояльность

За каждый уровень выше первого цена покупки падает на `LoyaltyDiscountStep`:

```
цена = округлить( Price × (1 − шаг × (уровень − 1)) )
```

Ограничения, зашитые в коде:

* цена никогда не опускается ниже **50 %** от `Price`;
* шаг не может быть больше **0.15** — при большем значении сервер возьмёт 0.15;
* `LoyaltyDiscountStep: 0` полностью отключает скидки.

| `LoyaltyDiscountStep` | I | II | III | IV |
|---|---|---|---|---|
| `0.05` | 100 % | 95 % | 90 % | 85 % |
| `0.10` | 100 % | 90 % | 80 % | 70 % |
| `0.15` | 100 % | 85 % | 70 % | 55 % |

Скидка касается **только покупки** за деньги. Бартеры она не удешевляет.

## Репутация за оборот

Чтобы репутация росла сама, без заданий, у каждого торговца есть три поля:

```json
"TurnoverReputationEnabled": true,
"TurnoverReputationInterval": 100000,
"TurnoverReputationGain": 0.1
```

Смысл: **каждые 100 000 оборота дают 0.1 репутации**.

| Оборот с торговцем | Начислено репутации |
|---|---|
| 99 999 | 0 |
| 100 000 | 0.1 |
| 250 000 | 0.2 |
| 1 000 000 | 1.0 |

Правила:

* Шаг начисляется **один раз** — сервер помнит, сколько шагов уже выдал.
* Начисление происходит в момент сделки (покупка, продажа, бартер), а не по таймеру.
* Если вы включили механику игроку, который уже наторговал на 500 000, — при первой же сделке он получит сразу `+0.5` за все прошедшие шаги.
* Выключение: `TurnoverReputationEnabled: false`, либо `Interval: 0`, либо `Gain: 0`. Отрицательные значения сервер заменит на `0` с предупреждением.
* Репутация не может превысить **9.99** — излишек просто срезается.

### Как подобрать значения

Пороги репутации и скорость её роста должны сходиться, иначе уровень недостижим.

Проверьте: при стандартных настройках (`100000` / `0.1`) игрок с оборотом 120 000 у Прапора имеет репутацию `0.12` — а для уровня II нужно `0.04`. Запас есть, прогрессия работает.

Если поставите `TurnoverReputationInterval: 1000000` при пороге `0.15` для IV уровня, игроки упрутся: оборота на 120 000 для IV хватит, а репутации `0.15` не наберётся никогда. Либо уменьшайте интервал, либо снижайте пороги репутации.

## Где это хранится — файл игрока

`$profile:SG_Traders\players\<SteamID64>.json`:

```json
{
    "SteamId": "76561198012345678",
    "Roubles": 45200,
    "Dollars": 120,
    "Turnovers": [
        { "TraderId": "PRAPOR",    "Amount": 128000 },
        { "TraderId": "THERAPIST", "Amount": 9400 }
    ],
    "Quotas": [
        { "Key": "S:PRAPOR:S:I:7", "CycleStamp": 5400, "Used": 2 },
        { "Key": "L:PRAPOR:AKM",   "CycleStamp": 5400, "Used": 3 }
    ],
    "ReputationEntries": [
        { "TraderId": "PRAPOR", "Amount": 0.2, "TurnoverRepSteps": 1 }
    ]
}
```

| Блок | Что это |
|---|---|
| `Roubles` / `Dollars` | Кошелёк игрока |
| `Turnovers` | Оборот по каждому торговцу — из него считается уровень |
| `Quotas` | Выбранные лимиты покупки и скупки за текущий цикл завоза |
| `ReputationEntries` | Репутация и сколько шагов оборота уже зачтено |

Ключи в `Quotas`:

| Ключ | Что ограничивает |
|---|---|
| `S:<торговец>:S:I:<номер>` | `MaxStock` товара с этим **порядковым номером** в массиве `Items` |
| `S:<торговец>:S:B:<номер>` | `MaxStock` бартера с этим номером в массиве `Barters` |
| `L:<торговец>:<classname>` | Лимит скупки этого предмета |

⚠️ **Лимит покупки привязан к порядковому номеру товара, а не к класснейму.** Если вы вставите новый товар в середину массива `Items` или поменяете строки местами, счётчики игроков «съедут» на соседние позиции. Безопасно **добавлять товары в конец** массива.

`CycleStamp` — время последнего завоза торговца. На завозе метка перестаёт совпадать, и счётчик читается как ноль — чистить ничего не нужно.

### Редактировать файлы игроков руками?

Технически можно, но только при **выключенном сервере**: профили держатся в памяти и перезаписываются при каждой сделке и при выходе игрока. Для разовых правок (выдать деньги, поднять уровень, снять репутацию) используйте админ-панель — она делает то же самое безопасно и сразу.

## Быстрая шпаргалка

| Хочу | Что менять |
|---|---|
| Быстрее качаются уровни | Уменьшить `LoyaltyThresholds` |
| Уровни только за деньги, без репутации | `LoyaltyReputationThresholds: []` |
| Уровни только за задания | `TurnoverReputationEnabled: false` + пороги репутации оставить |
| Больше скидка у «своих» | `LoyaltyDiscountStep` (до `0.15`) |
| Отключить скидки совсем | `LoyaltyDiscountStep: 0` |
| Быстрее растёт репутация | Уменьшить `TurnoverReputationInterval` или увеличить `TurnoverReputationGain` |
| Разные темпы у разных торговцев | Эти три поля есть у каждого торговца отдельно |

## Частые ошибки

| Симптом | Причина |
|---|---|
| Игрок наторговал, а уровень не растёт | Не хватает **репутации** — уровень требует обе шкалы |
| Уровень упал после правки конфига | Пороги повысили; уровень пересчитывается на лету |
| Репутация стоит на одном месте | `TurnoverReputationEnabled: false`, или `Interval`/`Gain` равны нулю, или шаг ещё не пройден |
| Скидки нет | `LoyaltyDiscountStep: 0` или товар — бартер (скидка на бартеры не действует) |
| В логе `WARNING: ... negative TurnoverReputationInterval` | Отрицательное значение; сервер заменил на `0`, прогрессия у этого торговца выключена |
