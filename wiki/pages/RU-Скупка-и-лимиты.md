# Скупка и лимиты

[🇬🇧 English version](EN-Selling-And-Limits)

**Что это:** как торговец решает, брать ли вашу вещь и сколько за неё заплатить. Настраивается полями `SellCategories`, `SellPriceRatio`, `DefaultSellLimit`, `SellLimits`, `SellValueOverrides`, `HotItemPool` и `HotItemBoost` в файле торговца, плюс `DefaultSellValue` и `SellConditionFloor` в главном конфиге.

---

## Формула цены скупки

За каждую штуку торговец платит:

```
цена = округлить( база × SellPriceRatio × горячий × состояние × объём )
```

| Множитель | Откуда берётся |
|---|---|
| **база** | Цена этого предмета у данного торговца → иначе `SellValueOverrides` → иначе `DefaultSellValue` |
| **`SellPriceRatio`** | Поле торговца. `0.5` = половина цены, `0.3` = треть |
| **горячий** | `HotItemBoost`, если этот предмет — «горячий товар» текущего цикла. Иначе `1.0` |
| **состояние** | От здоровья предмета: `SellConditionFloor + (1 − SellConditionFloor) × здоровье` |
| **объём** | Для расходников — доля оставшегося содержимого. Для целых предметов `1.0` |

Цена **не падает со временем** — торговец не «дампит» цены, сколько бы вы ему ни сдали. Единственное ограничение по количеству — лимиты скупки (ниже).

### Разбор множителей

**База.** Порядок поиска:

1. Предмет есть в `Items` этого торговца → берётся его `Price`.
2. Иначе есть запись в `SellValueOverrides` → берётся её `Value`.
3. Иначе — `DefaultSellValue` из `SGTradersConfig.json` (по умолчанию `300`).

**Состояние.** При `SellConditionFloor: 0.25`:

| Здоровье предмета | Множитель |
|---|---|
| 100 % | 1.00 |
| 60 % | 0.70 |
| 20 % | 0.40 |
| 0 % | 0.25 |

Крайние значения: `SellConditionFloor: 1.0` — состояние не влияет вообще; `0.0` — сломанное не стоит ничего. У предметов без здоровья (патроны, еда) множитель всегда `1.0`.

**Объём.**

* **Сыпучие патроны** — платят за оставшиеся патроны: пачка на 60, осталось 20 → множитель `20/60`.
* **Магазины** — платят полно, сколько бы патронов в них ни осталось.
* **Расходники с количеством** (еда, вода, бинты, бензин) — платят пропорционально остатку, но не меньше 5 %.
* Всё остальное — `1.0`.

### Примеры на цифрах из стандартной поставки

| Что сдаём | Кому | Расчёт | Получаем |
|---|---|---|---|
| `AKM`, исправный | Прапор (`ratio 0.5`, цена 25 000) | 25 000 × 0.5 × 1.0 | **12 500 ₽** |
| `AKM`, здоровье 60 % | Прапор | 25 000 × 0.5 × 0.70 | **8 750 ₽** |
| `Megaphone`, «горячий товар» | Скупщик (`ratio 0.3`, цена 3 000, `boost 1.5`) | 3 000 × 0.3 × 1.5 | **1 350 ₽** |
| `BearPelt` — нет в ассортименте | Скупщик (`ratio 0.3`, база = `DefaultSellValue` 300) | 300 × 0.3 | **90 ₽** |
| Патроны `Ammo_762x39`, 20 шт. в пачке | Прапор (`ratio 0.5`, цена 1 200) | 1 200 × 0.5 × 20/60 | **200 ₽** |

Последняя строка — главная причина поднять `DefaultSellValue` или прописать `SellValueOverrides`: без них любой незнакомый предмет стоит копейки.

## `SellCategories` — что торговец вообще принимает

Торговец берёт вещь только если её категория есть в его списке. Если категории нет — в списке продажи предмет просто не появится.

```json
"SellCategories": [ "WEAPONS", "MAGAZINES", "AMMO" ]
```

Доступные значения (регистр не важен):

| Значение | Что попадает |
|---|---|
| `WEAPONS` | Огнестрельное оружие |
| `MAGAZINES` | Магазины |
| `AMMO` | Патроны |
| `MEDICAL` | Медикаменты |
| `FOOD` | Еда и питьё |
| `CLOTHING` | Одежда, жилеты, рюкзаки |
| `VESTS` | То же, что `CLOTHING` (старое название, работает) |
| `BACKPACKS` | То же, что `CLOTHING` (старое название, работает) |
| `TOOLS` | Инструменты, прицелы, модули оружия, ближний бой |
| `VALUABLES` | Ценности: аккумуляторы, радиостанции, шкуры, запчасти, семена |
| `ALL` | Все перечисленные категории сразу |

Категория определяется по классу предмета автоматически. Если хотите принудительно отнести товар к категории — это поле `Category` у товара, оно **не** влияет на скупку, только на вкладку в ассортименте.

⚠️ Даже `ALL` не заставляет торговца брать **всё подряд**. Предметы, которые не удалось отнести ни к одной категории (брёвна, доски, строительный мусор), не покупаются никогда — их «категория» пустая.

## Лимиты скупки

Защищают экономику: не дают одному игроку сдать 500 автоматов за вечер.

```json
"DefaultSellLimit": 10,
"SellLimits": [
    { "ClassName": "Morphine",   "MaxPerRestock": 5 },
    { "ClassName": "BloodBagIV", "MaxPerRestock": 4 }
]
```

| Поле | Что делает |
|---|---|
| `DefaultSellLimit` | Общий лимит: столько штук **одного** предмета торговец купит у **одного игрока** за цикл завоза. `-1` = без ограничений. |
| `SellLimits` | Личный лимит на конкретный класснейм. Перекрывает общий. |

Важные детали:

* Лимит **личный**, как и `MaxStock` у товаров: у каждого игрока свой счётчик.
* Счётчик обнуляется на завозе (`RestockMinutes`). При `RestockMinutes: 0` лимиты **не восстанавливаются никогда**.
* Запись в `SellLimits` с `MaxPerRestock` ≤ 0 считается некорректной и удаляется при загрузке. Чтобы снять личный лимит — удалите запись, а не пишите `0`.
* Если игрок пытается продать больше, чем осталось по лимиту, продастся только часть: «Продано частично — лимит скупки торговца исчерпан».
* Если лимит уже выбран: «Торговец больше не берёт этот товар до завоза».

## `SellValueOverrides` — своя цена на скупку

Нужно, когда торговец **принимает** предмет, но **не продаёт** его, и дефолтные 300 не устраивают.

```json
"SellValueOverrides": [
    { "ClassName": "BearPelt",  "Value": 2500 },
    { "ClassName": "WolfPelt",  "Value": 1800 }
]
```

При `SellPriceRatio: 0.3` медвежья шкура будет уходить за `2500 × 0.3 = 750`.

`SellValueOverrides` **не** делает предмет товаром — в ассортименте он не появится. Это только цена для скупки.

## «Горячий товар»

Механика Скупщика: каждый цикл завоза торговец случайно выбирает один предмет из списка и платит за него больше.

```json
"HotItemBoost": 1.5,
"HotItemPool": [
    "Battery9V", "CarBattery", "SparkPlug", "PersonalRadio", "Rangefinder",
    "Megaphone", "CableReel", "ElectronicRepairKit", "MetalPlate", "CanisterGasoline"
]
```

* Работает, только если `HotItemBoost` **больше 1.0**. По умолчанию `0.0` — выключено. Значения `0.5` или `1.0` тоже ничего не делают.
* Пустой `HotItemPool` — тоже выключено.
* Предмет выбирается заново на каждом завозе и сохраняется в `SGTradersState.json`, поэтому переживает рестарт сервера.
* Игрок видит такой товар с пометкой **ГОРЯЧЕЕ** и процентом надбавки.
* Битые класснеймы в списке удаляются при загрузке с предупреждением.

Хотите «горячий товар» у другого торговца — просто впишите ему `HotItemBoost` и свой `HotItemPool`.

## Что торговец не возьмёт

* **Предмет с содержимым.** В рюкзак что-то положили, на оружие повесили прицел — вещь помечается **ЗАПОЛНЕН** и не продаётся, пока не опустошите. Ничего из содержимого не пропадает и в цену не закладывается — сначала вытащите, потом продавайте по отдельности.
* **Категория не в `SellCategories`.**
* **Больше, чем осталось по лимиту** — продастся частично.

### Сборка оружия и автовыбор покупателя

Оружие с навесными модулями продаётся двумя способами:

1. **Целиком** — ствол плюс все модули одной сделкой (пометка **СБОРКА**).
2. **По отдельности** — можно снять и продать один модуль.

Модули при этом продаются **тому торговцу, который платит за них больше всех**, а не обязательно тому, у кого открыта доска. В интерфейсе это видно по стрелке `→ Механик` рядом с ценой, а после сделки появится сообщение «Продано торговцу …». Деньги приходят в валюте того торговца, оборот и репутация тоже начисляются ему.

## Настройки, которые стоит поменять в первую очередь

| Хочу | Что менять |
|---|---|
| Чтобы торговцы платили больше/меньше в целом | `SellPriceRatio` у каждого торговца |
| Чтобы «мусор» стоил не 300 | `DefaultSellValue` в главном конфиге |
| Чтобы состояние не влияло на цену | `SellConditionFloor: 1.0` |
| Чтобы нельзя было сливать сотни стволов | `DefaultSellLimit` (например `5`) |
| Чтобы Скупщик брал всё, но дёшево | `SellCategories: ["ALL"]` + низкий `SellPriceRatio` |
| Свою «биржу» дефицита | `HotItemBoost` + `HotItemPool` у нужного торговца |

## Частые ошибки

| Симптом | Причина |
|---|---|
| Предмет не появляется в списке продажи | Его категории нет в `SellCategories` торговца |
| Всё сдаётся по 90 ₽ | Предмета нет ни в ассортименте, ни в `SellValueOverrides` — работает `DefaultSellValue: 300` |
| «Горячий товар» не работает | `HotItemBoost` ≤ 1.0 или пустой `HotItemPool` |
| Лимит скупки не восстанавливается | `RestockMinutes: 0` — автозавоз выключен |
| Рюкзак не продаётся | Внутри что-то лежит, пометка **ЗАПОЛНЕН** |
| В логе `WARNING: ... invalid sell limit entry — removed` | `MaxPerRestock` ≤ 0 или пустой `ClassName` в `SellLimits` |
